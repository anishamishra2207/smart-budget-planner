# Smart Budget Planner Agent

**Overview:** The Smart Budget Planner is a real AI agent that helps users track expenses and make financial decisions. It demonstrates a genuine plan-act loop: the agent receives a user goal, formulates a plan, calls tools to gather or update information, observes the results, and uses those results to decide on the next action. The agent maintains persistent memory across multiple turns, allowing users to set budgets, record expenses, and check affordability without repeating prior context.

**Required Tools:** The agent implements two core tools that the LLM actually invokes through its function-calling mechanism. `add_expense(item, amount, category)` validates and stores expenses in session memory, returning structured results that confirm the addition and update the remaining balance. `get_summary(category)` reads the actual session memory, calculates spending breakdowns by category, and handles empty categories gracefully. Memory is session-based and persists across turns in the same agent instance—no database is used. The conversation history in `message_history` grows with each turn, preserving the user's prior budget goals, expense records, and the agent's reasoning steps.

**Group-of-3 Add-on:** The project includes two additional features required for a 3-member group. `set_savings_goal(amount)` allows users to declare a savings target and the agent reports whether the goal is at risk based on current spending. `set_category_limit(category, limit)` enables per-category spending caps, and `get_category_overspending()` automatically detects and warns when a category exceeds its limit, producing clear messages like "WARNING: Food spending has exceeded its limit by ₹500."

**Honest Failure & Fix:** During development, the initial GitHub Models endpoint was in retirement brownout and returned a 410 error; additionally, an attempted model identifier produced a 404 "model not found" response. This broke the agent loop. The fix was to migrate the OpenAI-compatible client from the GitHub endpoint to the Groq API endpoint and use the stable `openai/gpt-oss-120b` model identifier. The tool-calling mechanism remained identical, only the base URL and API key changed, which validated that the agent design was endpoint-agnostic.
